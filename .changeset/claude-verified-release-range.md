Part of #720: the native Claude Code profile now accepts a fixture-verified declared release range (2.1.316 and 2.1.318 today; a release is accepted only when `tests/fixtures/claude_contract/<version>.jsonl` exists) instead of one exact version, and default discovery reads in-range captures with the verified adapter so `ahl improve --history` gets ordered events, tool names, call ids and structured outcomes on the current release. Entry types the profile does not handle are skipped with a count and a typed reason per type (`declared_non_event_entry` or `unknown_entry_type`) and never change an event; unknown extra fields on known types are ignored by one documented rule. Sources report `pin_compatibility: declared_range`, the adapter that read each capture and recorded versions as counts. New read-only `ahl sources claude pin-check --events FILE [--emit-skeleton PATH]` compares a capture with the contract at the field-name level, prints a content-free diff and a verdict (`compatible`, `compatible_with_unknown_types`, `incompatible`) and can emit a names-only fixture skeleton. `ahl doctor` (`claude_runtime_lag`) and the improve history receipt (`history.runtime_lag`) warn once when recorded releases exceed the newest verified one, and the analysis brief names the adapter of each capture and how many cases lack a declared order or tool names because of the descriptive adapter. Remaining for #720: a fixture for 2.1.317, so the contiguous range 2.1.316 to 2.1.318 is not yet declared.
