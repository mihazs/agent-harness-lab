Add the harness degradation report as a pure, offline module (`agent_harness_lab.memory.degradation`, schema `ahl-harness-degradation-v1`). It places each candidate-versus-baseline metric on the claim ladder (`not_observed`, `observed_difference`, `possible_regression`, `supported_regression_under_test`, with `causally_attributed` reserved and never produced), keeps `not_comparable` and `insufficient_evidence` as separate outcomes, and reuses the existing weighted-root Hoeffding interval and frozen worsening margin unchanged: a reduced success rate without enough independent roots stays an observed difference, a changed grader, bank or environment can never be reported as a regression, a changed cache state, timing or token boundary blocks an efficiency comparison, and a regression bound is never recomputed or replaced by a t-test or an invented probability. Metric contracts cover paired task success, preserved capability pass (naming the lost capability), agent error rate (infrastructure and unknown errors kept apart), time per assigned task, measured tokens (quality-gated), and descriptive duplicate, surface-presence and finding-coverage metrics, with no combined health rating. `check` rejects a claim whose typed numerics are null, and `trend` stays descriptive: repeated fixed-sample looks never produce a sequential claim. The `ahl history compare|trend` commands that load stored histories are not part of this change.
