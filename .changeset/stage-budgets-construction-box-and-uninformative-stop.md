Fix #739 (construction layer): `ahl improve` now splits its shared budget into preparation, construction, trials and refinement stages. Evaluation construction gets a time box (default 25% of `--timeout`, set with the new `--construction-fraction`) that the construction prompt states together with the seconds remaining; a pass that overruns it ends `budget_exhausted` with the typed reason `evaluation_construction_timeout`, and gets one more pass only when the remaining budget covers another box plus the trials allotment. The controller grades each task's `complete` control through the same grader invocation before any trial is charged and rejects a task that cannot finish inside the per-trial timeout (now an equal share of the remaining budget per planned trial, at most 180 seconds) with `evaluation_task_infeasible`. When no trial of either arm passes and both arms end every task alike, the run stops `inconclusive` with `evaluation_uninformative`, classified from execution facts only (timeouts, exit codes, tool-error records), with one exact next step and no second construction. A cooperative refinement reuses the frozen development and regression tasks, graders and controls (every copied byte checked against its frozen digest) and constructs only fresh held-out inputs; it starts only when the remaining budget covers its allotment (`refinement_budget_unavailable`). Every terminal receipt, including blocked, invalid and exhausted ones, carries `budget_stages` (seconds per stage, remaining budget and the options that raise it), and an exhausted run adds `budget_exhaustion` (evidence label, the stage that took the budget, what was and was not observed, no conclusion). Frozen graders, freeze-before-trial and the fresh held-out rule are unchanged. Controlled (Responses) construction does not yet get the time box or the refinement reuse.
