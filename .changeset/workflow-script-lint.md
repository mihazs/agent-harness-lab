Add `agent_harness_lab/sources/workflows_inventory.py`, a static inventory and heuristic lint of Claude Code workflow scripts (`.claude/workflows/*.js`). Scripts are never executed: a bounded standard-library lexer skips comments, strings and template text, and it checks that `export const meta = {` is the first statement and holds a plain literal with `name` and `description`. Anything else is `meta_not_first_literal`. The lexer also counts `import(`, `Date.now(`, `Math.random(` and no-argument `new Date` in code and records `phase()` titles. Results are labelled `static_lint_not_runtime_validation`, and a lexer doubt is `lint_inconclusive` with null counts, never a pass: a `/` after `}`, `++` or `--` is `regex_or_division_ambiguous`, an out-of-range `\u{...}` escape is `invalid_escape`, and a malformed script never fails the whole inventory. Project scripts on the `task_cwd`-to-root path follow the documented precedence: the closest directory wins, project beats personal and plugins are namespaced. Undocumented ties are `clash_unresolved`. Personal and plugin directories are read only when the caller declares them. `.claude/workflows/*.js` now classifies as a `contract_required` `workflow` surface, even beneath a `hooks` or `skills` directory, the harness inventory registers the lint as its `workflow` parser, and the capability table records the 2.1.248 and 2.1.269 gates. Codex has no workflow loader and returns `unsupported` with that evidence.
