An installing `ahl improve` run now sends a grader self-test failure (and other defects its own graders show) back to the evaluation author as a repair pass, naming the task, the control and the grader's bounded output, instead of ending `invalid_input`. An installing run builds its refinement evaluation afresh instead of reusing frozen tasks, so a control the baseline fails is not carried over and the refinement gets the same repairs. In a trial whose fixture is a git repository, the harness files AHL stages (instructions, skills, the trial plugin) are kept out of `git status`, so a grader that checks for a clean tree no longer fails both arms. When the first candidate of an installing run fixed a task and lost none while the authored regression controls failed in both arms, the second attempt keeps that candidate, does not propose again and builds the evaluation afresh with the invalid controls named (`controls_rebuilt`). An installing run no longer needs the same flip in two runs: it repeats only the tasks the candidate fixed, up to six runs in all, and installs when the candidate's pooled pass rate beats the baseline's by a one-sided exact test (p at most 0.05), so an intermittent baseline weakness no longer blocks a fix; `confirmation` now holds the pooled pass counts and the p-value instead of `fixed`, `fixed_once` and `lost`.
