BREAKING: `ahl improve` and `ahl skills invoke` now run the evaluate, improve, evaluate loop by default whenever `ahl.json` pins a task bank, with no loop flag or declaration needed. The baseline is scored first, each round improves one mechanism and re-evaluates it on identical frozen inputs, and the receipt carries the typed `loop` block (`stop_criterion`, `acceptance_source: default` and mode `relative_supported_improvement` when no score is declared, `certification: unverified`, `automatic_promotion: false`); `--max-rounds 1` is exactly one evaluate, improve, evaluate pass. The previous improve-first single pass stays reachable for one release as `--single-pass`, which is deprecated and removed after that release; its receipt says `loop.status: not_used`, `loop.reason: single_pass_requested` and `loop.deprecated: true`, and it does not combine with the loop flags. A run that cannot use the loop (no pinned bank, a controlled runtime, or an `--experiment-request`, which needs the starter bank) keeps its single pass and now says so in a `loop.status: not_used` block with the reason and one next step, and a loop run that a gate stopped before its first evaluation says `loop.status: not_started`; a loop flag or declaration without a pinned bank is still `blocked` with `loop_requires_frozen_bank`. Every pinned-bank `ahl improve` result now has a `loop` block instead of the fixed-bank comparison receipt: pass `--single-pass` to keep the old one. Adds the how-to "Improve until an acceptance score is reached", the explanation "Why the loop evaluates, improves, then evaluates" and a completed loop reference, and the skill now routes an improve request to `ahl skills invoke` with `--accept-score X --max-rounds N` instead of describing a manual loop (the manual loop remains only as the assisted fallback). Part of #817: constructing a frozen bank on first use for the loop and driving an `--experiment-request` bank with it remain.
