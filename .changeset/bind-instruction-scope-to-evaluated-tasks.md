Bind the governing scope of scoped instruction and rule rewrites to the evaluated tasks instead of the proposer's plan alone (#339). After the evaluation manifest is validated and before baseline or candidate trials run, `instruction_validation.bind` checks the plan's `task_cwd` against the task `cwd` values, where a task without one runs at the root, and checks that each task path lies below that `task_cwd` and an evaluated cwd. A task `cwd` counts only under the controlled Responses executor, which runs the trial there; elsewhere a manifest that declares one is refused. Task paths stay proposer-declared (`scope.task_paths_source`), so the bound scope drops the nested instructions and path rules only they make governing (`scope.task_path_scope`). A plan that declares an unrelated `task_cwd` or task path to reach a sibling `CLAUDE.md`, `AGENTS.md` or rule is refused as `instruction_validation_blocked` (`task_cwd_not_evaluated`, `task_path_not_evaluated`, `task_path_scope_unbound`). The report records `scope.source: "evaluation_manifest_task_cwds"` and `scope.task_cwds`, `check_scope` enforces the bound scope, and `current` reports `scope_unbound` for a scope that was never bound, so no recommendation rests on a proposer-declared scope.
