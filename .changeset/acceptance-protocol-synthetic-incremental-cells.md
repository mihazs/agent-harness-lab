Let a second run of the real-project acceptance protocol find the first. `scripts/isolated_project_check.py` made a new random worktree path for every check, and the run store of `ahl improve` is keyed by the project path, so the incremental step could never see the earlier run: the second receipt carried no `incremental` block. Checks of one repository that run one after another now use the same worktree path (`ahl-isolated-<hash>-<slot>`; overlapping checks take the next slot, a leftover directory from an interrupted check is skipped and never followed, and the directory is still removed on exit). The synthetic equivalent behind `task test:isolated` (and the default `task test`) now runs a second `ahl improve` through the check and requires it to name the first run, to say what became of its candidate (`ignored`, `applied` or `edited`), to label the earlier score `historical_observation` beside its own `fresh_evaluation` trials (or alone when it evaluated nothing), and to end `blocked` with `candidate_already_regressed` without evaluating again when the first run measured the candidate worse; a second check that does not share `AHL_STATE_HOME` must not see the first. The how-to's incremental step states these criteria instead of the failure it recorded while the slice was open, and links the stress matrix instead of the open slice. Part of #808.
