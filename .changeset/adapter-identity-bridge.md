Add `evaluation.adapter_bridge`, an identity-only JSON-envelope bridge for the one documented adapter runtime integration, the Claude Code `PostToolUse` and `PostToolUseFailure` hooks, and the decision record that investigated it. `probe_runtime` declares only the pinned Claude Code version and reports Codex and every other version as unsupported; it never reports a runtime as verified. `Bridge` binds each hook event to a run and call, keeps the original status and payload, answers with an empty reply so the runtime keeps the original output, and records a metadata-only ledger apart from private provenance. Malformed, oversized, unauthorized, other-run, duplicate-conflicting and cancelled events are handled without changing tool effects; a required bridge stops the execution and an optional one falls back to identity with a recorded error. `capability_receipt` and `verify_receipt` bind the bridge, adapter, spec and authorization digests and keep application evidence unknown unless observed; a fake runtime is never counted as supported-runtime evidence. `runtime_capability` still reports unsupported and now names the documented candidate and its blockers. Nothing calls the bridge by default and no hook is installed.
