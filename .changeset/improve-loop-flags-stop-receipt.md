Expose the evaluate, improve, evaluate loop on `ahl improve` and `ahl skills invoke`, opt-in. `--accept-score X`, `--max-rounds N`, `--plateau-rounds N` and `--on-regression stop|rollback_continue`, or a `loop` object in the project `ahl.json` or the user file, run the loop controller over the pinned frozen bank: the baseline is scored first, each round offers one mechanism to the preparation stage, the candidate (validated like a single pass and frozen) is re-evaluated against the best snapshot on identical frozen inputs, and held-out tasks are never run. Every run ends with exactly one typed stop criterion in an additive `loop` block of `workflow.json` (`ahl-loop-receipt-v1`: the resolved spec with the source of each value, the frozen inputs, `before`, `after`, `rounds[]`, `best_round`, `stop_criterion`, looks and alpha per look, the stage budget, `certification: unverified`, `automatic_promotion: false` and one remediation step), checked by a fail-closed `validate_receipt()`. The coarse statuses and exit codes map each criterion: `accepted` (0) for `accepted_without_change` and `acceptance_score_reached`, `requires_intervention` (1) for `budget_exhausted`, `interrupted` and `comparison_invalid`, `not_accepted` (3) for `max_rounds`, `plateau`, `regression`, `no_actionable_mechanism` and `evidence_insufficient`; an invalid declaration is exit 2 with its own reason, and a loop declaration without a pinned bank is `blocked` with `loop_requires_frozen_bank`, never a silent single pass. The controller counts the seconds spent before it started against the time ceiling and turns a port that reaches the budget into the `budget_exhausted` stop. Without a loop flag or declaration, every receipt, status and exit code is unchanged. Part of #814.
