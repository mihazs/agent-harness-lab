Add a read-only `api/gitea/v1` source for selected issues and pull requests of one explicitly named repository on a self-hosted Gitea instance. The selection names a canonical HTTPS instance root, `owner/repo`, the issue and PR numbers and what to capture (`comments`, `issues`, `pulls`, `reviews`); `http://` and non-canonical roots are refused, and nothing is enumerated. Identity is the instance host, port and path plus the owner/repository name and the issue/PR number or comment/review ID, so the same number on another host or repository stays distinct and a fork head keeps its own repository identity. The server version is recorded from `/api/v1/version` or marked `unknown`. Issues, PRs (base/head repository, branch and SHAs, state, draft, merged and merge commit), comments and reviews (state, commit, stale/dismissed/official) are hash-only records, and a closed issue, merged PR or approval never becomes a verified task outcome. Listings use `page`/`limit` with `Link` and `X-Total-Count`; incomplete pagination, 401/403/404/429 and spent budgets are explicit coverage states that block the checkpoint, while a missing review endpoint is an `unsupported_endpoint` gap. `ahl sources` accepts the Gitea configuration, a new `--authorization-env NAME` option or the existing `--authorization-file`, prints a `gitea_summary` on preview, and exits 3 when an import is blocked. Non-200 responses now raise `HTTPStatusError`, a `TransportError` carrying only the status code. Inline review comments, PR commits and files, timelines and CI evidence remain open.
