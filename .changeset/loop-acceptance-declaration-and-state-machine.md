Add the acceptance-score declaration and the evaluate > improve > evaluate state machine as a pure library (`agent_harness_lab.loop`), the first slice of the improvement loop. A frozen `LoopSpec` declares `accept_score` (a number or a per-area map), `accept_basis`, `regression_margin`, `noise_margin`, `max_rounds` (default 3, cap 10), `plateau_rounds`, `on_regression` and `alpha`, resolved from the command line, the optional user file, a project `ahl.json` `loop` object and documented defaults, with the source of every value named and a canonical digest that freezes the per-look error level `alpha / max_rounds`. Without `accept_score` the mode is `relative_supported_improvement` labelled `acceptance_source: default`; an absolute score is never invented, a per-area map needs declared areas, and no source can declare apply, global scope, promotion or certification. A table-driven machine and a pure `decide()` over classified inputs give one outcome and at most one stop criterion from a closed set, resolve unknown, vacuous or incomplete evidence to `evidence_insufficient` and never to accepted or improved, and raise `loop_order_violation` when improving without a valid evaluation of the current best or reporting a result without a post-improvement evaluation. Every new reason has a one-step remediation in the exit reason table. `ahl improve` behavior is unchanged; nothing runs the loop yet. The reference is `docs/loop-reference.md`.
