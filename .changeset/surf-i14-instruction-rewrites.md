Add `agent_harness_lab/sources/instruction_validation.py`, which validates scoped instruction and path-rule candidates. It runs the instruction and rule resolvers again on a baseline closure and a candidate closure, each made of the project's in-checkout instruction files with the staged copy laid over them. A candidate that changes a nested instruction or any rule file must declare an `instruction_plan`. The candidate is blocked when it edits outside the governing scope, edits a rule that matches no declared task path, adds an import cycle or missing import, changes shadowing without declaring it, drops a declared task path from a rule's `paths`, moves or removes a required text from the active context, or starts from a stale baseline. `ahl improve` writes the validation report and blocks before evaluation. `one_call.check_scope` now rejects a changed instruction or rule file outside the validated scope, and without one it rejects any nested file the frozen baseline does not hold. Active-context bytes are a secondary measurement. A reduction made by moving text out of the active context earns no credit, and length never selects a winner. Removing active guidance is `recommended` only when regression controls pass in trial workspaces that staged each version faithfully, and it still needs certification. The validation runs again before a recommendation is recorded.
