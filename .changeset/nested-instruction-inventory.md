Inventory nested instructions across the whole checkout. The Claude Code profile now walks the checkout without following links or entering nested repositories. Every `CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md` and `AGENTS.md` is classified against `task_cwd` as a launch ancestor, `on_demand_subdirectory` (its imports are resolved but stay `unknown`), a shadowed `AGENTS.md`, or `outside_task_scope`. `CLAUDE.local.md` is always `private_excluded`: it is hashed but never admitted, expanded or output. The optional declared `instruction_files` mode and `claude_md_excludes` patterns are inputs; an unknown mode leaves every project file `instruction_files_setting_unknown`, and exclude matching is labelled unverified. A walk over 100000 entries or depth 64 is `blocked`. Codex captures accept a caller-declared `CODEX_HOME`, where the first non-empty `AGENTS.override.md` or `AGENTS.md` applies. They also accept declared `project_root_markers` (`[]` limits discovery to the cwd) and `project_trust: declared_untrusted`, which drops project files. `CODEX_HOME` is never read unless declared. The surface inventory classifies nested instruction files as `recommendation_only` and registers an instruction parser that reports path-free relation, trigger and size facts, never loading evidence.
