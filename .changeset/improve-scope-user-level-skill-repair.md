Add `ahl improve --scope project|global|project+global` (also through `ahl skills invoke`). The default `project` scope never reads or writes user-level files and refuses a project directory that is, or sits inside, a user-level location. `--scope global` and `project+global` need an explicit `--agent codex|claude`, name the runtime's user skill directory (`$CLAUDE_CONFIG_DIR/skills` or `~/.claude/skills`, `~/.agents/skills`), and with `--repair-contracts` apply the existing deterministic skill-header repair there through the guarded journal, backup and rollback, one layer after the other under one budget. A project `ahl.json` carrying a `scope` key is rejected as invalid input. Every scope now returns `scope`, `layers`, `layers_evaluated`, `layers_changed`, `changed_files`, `recommended_files` and `blocked`, attributes each file to its layer, reports blocked, exhausted or failed layers as such and, for `project+global`, the runtime's documented load order. Model-driven evaluation of a user-level layer returns `blocked` with `global_scope_model_evaluation_unavailable` and changes nothing.
