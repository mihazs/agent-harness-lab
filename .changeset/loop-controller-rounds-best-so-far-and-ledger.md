Add the loop controller (`agent_harness_lab.loop.controller.run`), the third slice of the improvement loop. It drives the evaluate > improve > evaluate state machine over two injected ports, an evaluator and a proposer, and calls `decide()` for every decision. It keeps a best-so-far snapshot (the last candidate with a supported improvement) and always proposes the next round from it, so a regressed or inconclusive candidate stays in the ledger as evidence and never becomes the base. It offers one mechanism per round from the queue, keeps each mechanism's disposition for the run (`improved`, `accepted`, `rejected`, `inconclusive`, `deferred`) and stops `no_actionable_mechanism` when none is left. Before every improve step it reserves what re-evaluating needs, taken from the baseline evaluation's recorded usage, or the whole evaluation allotment when the usage is unknown, and otherwise stops `budget_exhausted` with the reason `reserve_for_evaluation_unavailable` before calling the proposer. A regression is investigated through an optional `investigate` port on the evaluator whose answer `candidate` alone lets `rollback_continue` go on; `other`, an unknown cause or any other answer stops the loop. A malformed score is recorded as incomplete and never accepts or improves, and a candidate or baseline run on other frozen inputs is `comparison_invalid`. Every move is recorded in a private round ledger (the `PrivateJournal` pattern used for campaigns: owner-only, one atomic file per event, at most `4 * max_rounds + 8` events, byte-identical for the same run and replayable through the state machine) kept outside the project, and the result states the number of looks and the per-look alpha. Three typed reasons are added, `loop_port_invalid`, `loop_ledger_invalid` and `loop_ledger_full`, each with a remediation in the exit reason table.

Fix the decision table of the loop state machine so that `on_regression: rollback_continue` applies only to a regression beyond `regression_margin`: a candidate-caused critical or per-area regression with a mechanism and a round left used to roll back and continue, and now always stops `regression`.

`ahl improve` still makes one pass and no command, receipt or exit code changes; nothing calls the controller yet. The reference is `docs/loop-reference.md`.
