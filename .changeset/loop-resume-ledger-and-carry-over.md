Make the evaluate, improve, evaluate loop resumable and incremental. `controller.resume()` continues a run from the last durable event of its round ledger: the chain, the state-machine order, the declaration digest and the newest event (kept in a new `head.json`) are verified first, a changed declaration is `resume_spec_changed`, other frozen inputs, baseline, mechanism queue or carried dispositions are `resume_inputs_changed`, and a run or resume that holds the case makes a second one `resume_busy`; none of them runs anything. A stopped run is returned as recorded with no evaluator or proposer call. An evaluation that was running when the run stopped is never counted: its round is recorded `abandoned` (no score, one round and one non-improving step counted, its mechanism back in the queue), the trials `evaluator.settle()` reports stay charged, the clock continues from the later of the caller's seconds and the last recorded time, and an evaluation whose requests cannot be settled is not repeated: the run ends `interrupted` with `stop_reason: unresolved_request` and a reconcile step. A new `resumed` ledger event records each resumption, and a resumed run reaches the stop an uninterrupted one reaches with the same charged trials and time.

A later `ahl improve` loop run reads the previous run through the incremental detection (#806) and adds a bounded `carry_over` block to its `loop` receipt: the previous run's `rejected`, `inconclusive` and `deferred` mechanisms are not offered again, the earlier scores sit beside the fresh baseline evaluation as a labelled historical observation (never its replacement, never a trial, never an input to a decision), and a harness edited outside the earlier candidate, other frozen inputs or an unknown relation reopen the mechanisms, with no delta across other frozen inputs. Carried dispositions and history are capped at fifty and ten with `truncated` provenance. `ahl improve --resume RUN_ID` now also returns the receipt of a finished loop run, after checking it and its round ledger; an interrupted run is still not continued by the command. Without a resume or an earlier loop run every receipt, status and exit code is unchanged. Part of #815.
