A second `ahl improve` on the same project now reads the first and reports the delta. Each run records the harness files it saw and the candidate it froze (`harness-states.json`, private run store only), and a later run adds an `incremental` block to `workflow.json`: whether the earlier candidate was `applied`, `ignored`, `partially_applied` or `edited` (read from file bytes and modes, `unknown` when the harness scope changed), whether the earlier receipt ended `candidate_regressed` (read from the receipt, never inferred), the harness paths that changed, the earlier score as a labelled `historical_observation` beside this run's own `fresh_evaluation` (subtracted only when every frozen input is identical), and which stages were rerun or skipped. A candidate that an earlier run already measured worse, for a cause the candidate owns, on the same baseline, scope and runtime, now ends `blocked` with the new typed reason `candidate_already_regressed` (exit 3) before any evaluation is constructed or run. Earlier trials are never reused as fresh execution, and an unreadable record is reported as `unavailable`, never as a first run. The loop round ledger and the reuse of deterministic analysis stages are not part of this change.
