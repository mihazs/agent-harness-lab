Add `workflow_contract_v1` to `agent_harness_lab/hooks_contract.py`, which stages Claude Code workflow scripts (`.claude/workflows/*.js`) under the same executable contract as hooks. `stage_workflows` builds journal snapshots without writing the project. The static workflow lint is a hard gate: a candidate whose `meta` is not the first literal, that uses `import(`, `Date.now()`, `Math.random()`, a no-argument `new Date()` or a static `import`, or whose lint is inconclusive is blocked before any run, and so is a removed, group- or world-writable or nested-repository script. A passed unit is admitted by `Journal.prepare(..., hook_contract=...)` like a hook unit and resolves its change-plan operations, but never lifts the deferred `hooks` surface. Analysis never runs a workflow. `trial_request` only describes a native run inside an isolated trial workspace outside the project, with `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` capped at 2 and an args fixture of at most 2048 bytes, and the caller runs it. `outcome` returns `recommendation_only` with a patch when there are no runs, and `inconclusive` when the runs are malformed. It returns `improved` only for graded baseline and candidate runs of such requests. Codex has no workflow loader, and every workflow document records that.
