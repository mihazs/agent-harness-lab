Aim `ahl improve` at declared capability areas and gate adoption per area. `ahl improve --area ID` (repeatable) runs only the pinned-bank tasks that carry a selected area, sizes the shared trial budget to them and checks the selection before any model call (`area_selection_undeclared`, `area_duplicate`, `area_selection_empty`, `area_selection_requires_pinned_bank`, `area_selection_requires_development_regression_and_heldout`). A project that declares areas now gets an `area_gate` block (schema `ahl-area-gate-v1`) beside the before/after guard: each area is `scored`, `provisional` or `no_evidence`, only a scored area can pass or regress, and a scored area whose paired delta falls below the negative regression margin ends the run `blocked` with the new typed reason `area_regressed`, one remediation step and an `investigation.json`, even when the pooled result did not fall; an unmeasured area is listed in `not_measured` and never counts as a pass or a regression. The loop gates every paired evaluation the same way (`Evaluation.regressed_areas` is the `area` regression, which stops the loop with `regression`). The block, and `ahl score --area` when it narrows the report, carry a `multiplicity` note with the number of areas examined, because no interval is corrected across areas. The exported evaluation manifest keeps a tagged task's `areas`. No statistic is added: the numbers are the guard's paired root means and interval over each area's pairs. Documented in `docs/gate-adoption-per-area.md` and `docs/area-gate-reference.md`.
