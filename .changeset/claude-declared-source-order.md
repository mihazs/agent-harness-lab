Add a versioned within-line source order to pinned Claude Code 2.1.316 captures. Several events from one native line (content blocks plus response usage/stop facets) used to share one `capture_order`, so method selection excluded those cases. Each event now also records `source_order_profile: "claude-native-order-v1"`, `source_suborder` (the content-array position, with usage and stop facets after the line's blocks) and `source_order_segment` (the physical file). Within one file and profile, method selection treats a strictly increasing `(capture_order, source_suborder)` as declared capture order. It reports these cases in `method_selection.inputs.source_order` and in the recurrence and matching coverage, and lists ties without a usable subordinal and cases that span files as still unordered. Records spanning files of a project-root journal stay unordered even when their offset ordinals increase. The subordinal is not execution or causal order and adds no outcome or independence label. Event IDs, journal record identities and revisions, collection fingerprints and duplicate-UUID checks ignore the new fields, so existing values are unchanged. Inputs without the fields keep identical analysis output and receipts. The schema rejects partial declarations and unknown profiles.
